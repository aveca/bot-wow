# P0.7 — Vérification cryptographique de l’archive R2 BOT-WOW

**Date :** 28 octobre 2026  
**Dépôt :** `aveca/bot-wow`  
**Objet R2 :** `botwow-binaries/casinobabe-fishing-1.2.0.zip`  
**Décision :** **SHA-256 CONFORME à l’empreinte de référence fournie**  
**Portée :** lecture seule sur l’objet R2 ; aucun changement de production.

## Résultat observé

Le SHA-256 a été calculé dans un Worker temporaire Cloudflare avec un binding R2 en lecture seule. Le résultat a été extrait des logs Cloudflare Workers Observability via l’API de télémétrie.

## Méthode et preuve technique

Le connecteur Cloudflare renvoyait le corps binaire de l’archive sous forme de texte UTF-8 altéré. Cette réponse n’a donc pas été utilisée pour calculer une empreinte.

Deux essais de déclenchement HTTP du Worker temporaire via `workers.dev` ont échoué à cause des restrictions de réseau des outils. Les Workers de ces essais ont été désactivés puis supprimés ; l’absence a été vérifiée.

La méthode ayant produit le résultat a utilisé :
1. un Worker temporaire dédié, sans sous-domaine public activé ;
2. un binding R2 pointant uniquement vers `botwow-binaries` ;
3. une file Cloudflare temporaire et un unique message pour déclencher le traitement, la limite de cinq déclencheurs Cron du compte empêchant cette méthode-là ;
4. le calcul `crypto.subtle.digest("SHA-256", bytes)` sur le tableau d’octets obtenu par `R2_BINARIES.get(...).arrayBuffer()` ;
5. la lecture du log `R2VERIFY_RESULT` dans le dataset `cloudflare-workers`.

Preuve observabilité : événement du service temporaire `botwow-r2-sha256-once-20261028`, type d’événement `queue`, batch size 1, horodatage UTC correspondant à `2026-10-28T05:49:36.027Z`. La charge utile du log rapporte le SHA-256, la taille, le résultat de la comparaison et les contrôles de structure ZIP indiqués ci-dessus. Le texte et les octets de l’archive n’ont pas été publiés dans le rapport.

## Nettoyage vérifié

Après la lecture du résultat, l’API Cloudflare a confirmé :
- consommateur de queue supprimé : HTTP 200 ;
- Worker temporaire supprimé : HTTP 200 ;
- file temporaire supprimée : HTTP 200 ;
- nouvelle liste des Workers : Worker temporaire absent ;
- nouvelle liste des queues : file temporaire absente.

Aucune sous-domaines workers.dev n’a été laissé activé par la méthode finale.

## Limites restantes

Ce contrôle démontre que les octets réels actuellement lus dans R2 ont le SHA-256 indiqué et que cette empreinte correspond à la valeur de référence fournie. Il confirme aussi l’intégrité structurelle du répertoire central ZIP et la présence des entrées nommées `VERSION` et `MANIFEST.json`.

**Ce rapport ne prétend pas avoir décompressé puis validé le contenu de `VERSION`, le JSON de `MANIFEST.json`, ni les empreintes individuelles des fichiers référencés par ce manifeste.** Il ne démontre pas à lui seul la provenance du build ou que les sources actuelles reproduisent la même archive. Ces vérifications doivent rester distinctes de la correspondance SHA-256.

## Conclusion

**SHA-256 CONFORME** : l’archive R2 `casinobabe-fishing-1.2.0.zip` a été lue et hachée directement dans Cloudflare, et le SHA-256 obtenu correspond exactement à la référence annoncée. La taille réelle est de 1 387 543 octets, le répertoire central ZIP est lisible et les entrées `VERSION` et `MANIFEST.json` sont présentes.

La vérification du contenu des fichiers internes du manifeste et de la provenance reproductible du build reste une étape distincte avant d’affirmer une certification complète de toute la release.
