What the licence runs

The fishing loop, the schools, the planner, the walk between spots, and the way back after a death. Each one is in the runtime, with tests behind it.

Cast, bite, catch

It casts, watches the bobber and clicks the bite. The logged median from bite to click is 308 ms. If the bobber is not clear, it does not click.

Schools it remembers

Spots stay on disk: confidence, sample size, export and import, atomic saves. A school is kept after more than one sighting.

Rounds in three modes

Nearest neighbour and 2-opt on legs it has actually timed. Cautious, balanced, or explore. The browser demo runs the same planner on simulated data.

Walks the round

Minimap odometry and a closed-loop heading. A step counts only when the character’s position changes. If movement stalls, it recovers briefly, then stops.

Back after a death

It reads the corpse and the player on the world map, walks back, and continues only after the character is alive again.

Reads the window

PrintWindow capture and window-message clicks. An emergency stop is always armed. It does not inject into the game process.

How it works

Three steps, all outside the game process. The browser demo lets you inspect the planner without installing anything.

1. Read the window

A runtime addon observes game state. The client captures the window as pixels. It does not read process memory.

2. Choose the round

Saved spots and the planner propose an order. You can try the same planner in the browser on simulated data.

3. Click as a window message

The click is sent to the window, not injected into the client. An emergency stop is always armed.
