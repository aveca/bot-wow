Capabilities

A product focused on fishing

Not a bundle of eight roles. One product, built around fishing, that owns its limits.

Available

Float detection calibrated on real captures

Day/night water hue ranges, texture discrimination, area threshold. Bite → click latency is instrumented (measured median: 308 ms) and the click delay was tuned with measurement campaigns, not intuition.

Available

Spot memory that survives restarts

Spots are stored in a versioned database (migrations, backups, atomic writes). Export and import are supported: a map can be corrected, completed or shared without losing observation history.

Available

Optimised rounds, parity-tested

The planner ranks legs by expected cost — measured time, mob risk, failure probability — then optimises the order (nearest neighbour + 2-opt). The JS planner of this site and the Python bot are compared on the same map at every build.

In development

Movement between fishing spots

The minimap odometer and the movement controller are implemented and tested (zero drift at rest, arrival confirmed by observation). Full spot-to-spot travel is still being validated in game: we do not claim it works end-to-end yet.

Available

Background mode

The bot reads pixels and sends inputs without taking focus — measured in our sessions. Anti-virus software may flag screen-reading tools; the install guide says so up front.

Planned

Corpse-run recovery after death

Today the bot stops safely and asks for a human after death. The failure chain has been identified (state machine, navigation to corpse, confirmation of resurrection) and is being implemented. It is announced as planned — not as working.

Demonstration

The map and the round, for real

The browser demo uses exactly the same planner as the local bot — parity between both implementations is verified at each build. Change the mode or the number of spots: the round is recomputed live.
