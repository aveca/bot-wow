What the licence runs

These are the capabilities in the Casinobabe fishing runtime: the cast loop, the schools, the planner, the walk, and the return after a death.

Reads pixels, never the process

The client captures the WoW window with the Windows PrintWindow API, so the game does not need the focus. Inputs are sent as window messages. The addon only reads game state; it never simulates input.

Float detection by colour, then a confirmation

The float is located on the captured frame with an HSV threshold, and the bite is confirmed before the click is sent. Reading memory or injecting into the game process are permanent refusals — they are not part of this design.

Spot memory and route planner

Fishing spots are persisted (versioned schema, atomic writes, export/import), and the planner computes rounds with nearest-neighbour plus 2-opt over measured legs, in three modes. F9 stops the run.

In the runtime

Each item below is implemented in aveca/Casinobabe on feat/fishing-route-intelligence-v2, with tests in that repository.

Cast, bite, catch

Casts, watches the bobber and clicks the bite. The logged median from bite to click is 308 ms. If the bobber is not clear, it does not click.

Walks the round

Minimap odometry and a closed-loop heading. A step counts only when the measured position moves toward the school. If movement stalls, it tries a short recovery, then stops.

Back after a death

Reads the corpse and the player on the world map, walks back, and continues only after the character is alive again.
